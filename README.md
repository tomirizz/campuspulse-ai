# CampusPulse AI · v0.3

Учебный помощник для кейса GDG Astana, Build with AI. ИИ и внешние сервисы — **Google Gemini / Vertex AI, Google Calendar, Agent Engine, Cloud Run и Firestore**. Собственные функции на Python выполняют расчёты, поиск и проверки, как разрешено ТЗ. Qwen/Ollama и GitHub-инструмент исключены из работающей версии; репозиторий остаётся на GitHub.

## Для команды

Общий репозиторий: [tomirizz/campuspulse-ai](https://github.com/tomirizz/campuspulse-ai). После принятия приглашения участник может скачать код, запускать сайт у себя и отправлять изменения. [Короткая инструкция для напарника](CONTRIBUTING.md): открытие проекта, запуск на Mac/Linux и Windows, работа в своей ветке.

Для совместной разработки используйте клон репозитория, а не отдельные ZIP-копии. Через GitHub синхронизируется код; личные задания, материалы и настройки каждого компьютера остаются локальными.

## Запуск

Живой деплой: https://kentucky-individuals-adrian-volleyball.trycloudflare.com/

На Mac откройте **«Запустить CampusPulse.command»**. Либо:

```bash
bash scripts/run.sh
```

Нужны Python 3.11–3.13 или `uv`; первое создание окружения требует интернета. Адрес: `http://127.0.0.1:8765`. Остановка — Ctrl+C. Если старая версия уже работает, сначала остановите её и запустите новую. Для Windows: создайте venv, установите `requirements.lock`, затем запустите `python -m uvicorn campuspulse.server:app --host 127.0.0.1 --port 8765 --no-access-log`.

**Пользователь не вводит API-ключ.** Google Gemini работает с серверными Application Default Credentials, Calendar — через кнопку входа Google. Владельцу приложения нужна однократная настройка Google Cloud и OAuth. Пока она не завершена, приложение явно работает **без ИИ**: формулы, формы, поиск, квесты, диагностика и календарный диалог доступны, но облачный ответ не имитируется. Режимы: `auto`, `tools`, `gemini`, `remote`.

## Что добавлено

1. **Силлабус → задания:** точные строки, явные дата/время, список недостающих полей. Пользователь проверяет предложение, вводит курс и длительность и сохраняет его с цитатой. Автоматических выдуманных сроков нет.
2. **«Что, если…»:** исходный и новый план по одному алгоритму и одному времени проверки, перемещённые блоки, разница минут, риски. Предпросмотр не меняет рабочие настройки. Пример чата: «Что если 2 часа в день?».
3. **Поиск по всем материалам:** точные цитаты с файлом, страницей, строкой и смещением; похожие фрагменты с разными числами помечаются как повод сверить контекст, а не доказанное противоречие.
4. **Нужная оценка:** подтверждённые пользователем веса, баллы и максимумы; взвешенная сумма, один неизвестный компонент, проверка суммы весов 100%, недостижимой цели и округление вверх. Можно прикрепить цитату правила из силлабуса.
5. **Учебные квесты:** вопросы «восстанови термин» из реального загруженного конспекта. Эталоны подтверждаются перед началом. Проверка по фиксированному правилу, прогресс, продолжение после перезагрузки, 10 XP за первый правильный ответ на уникальный факт. Повторный запрос и новая тренировка того же факта не дублируют XP.
6. **Проверка кода:** настоящая диагностика синтаксиса Python/JSON, файл, строка, столбец, текст ошибки. Код не исполняется. В чате можно отправить блок ```python или ```json с кодом.
7. **События Google Calendar через диалог:** «Запланируй хакатон на 17 октября в 13:00»; неполная команда вызывает уточнение. Контекст сохраняется в сессии. Часовой пояс — из настроек, длительность без указания — видимые 60 минут по умолчанию (изменяется в настройках). Есть проверка пересечений, отмена незавершённого запроса, повтор после сбоя с тем же ID и ссылка на созданное событие. События основного Google-календаря исключаются из свободных часов планировщика.

## Что подтверждено и что ожидает подключения

Код, локальные тесты и браузерные сценарии проверены; см. [отчёт v0.3](docs/verification-v0.3.json). Интеграция Google Calendar проверяется контрактными тестами на границе API, **не записью в реальный аккаунт**. Live Gemini, OAuth Calendar, Firestore, Cloud Run и Agent Engine ещё не проверены: облако ранее отложено владельцем. Подготовленный запрос без разрешения Google не выдаётся за созданное событие.

Для полного выполнения ТЗ обязательны живой Gemini и развёртывание Agent Engine. Презентация отложена до финального продукта; сохранённый файл v0.1 является старым черновиком.

## Проверяемые ответы

Gemini выбирает инструменты и ID существующих фактов. Числа, цитаты и финальные формулировки вставляет сервер. Свободный текст модели не может установить оценку, дедлайн, XP или исполнить код. У результатов есть «Почему?» с формулой, входами, источником и ограничениями.

События создаются отдельным детерминированным обработчиком **только по прямой команде пользователя**. Он не называется автономным решением Gemini в журнале. Документы и ответы ИИ не имеют полномочий создавать события или менять данные. Пользователь видит реальные вызовы и результаты, а не скрытые рассуждения.

Сессии изолированы случайной HttpOnly cookie. OAuth-токены зашифрованы и не попадают в контекст модели, ответы API или журнал инструментов. Локально данные хранятся в SQLite; облачный адаптер — Firestore. Сессия привязана к браузеру; синхронизации нескольких устройств пока нет. Сканированные PDF требуют предварительного OCR. Поиск лексический, календарь основной, события одноразовые, калькулятор рассчитан на взвешенную сумму; это честные границы версии.
