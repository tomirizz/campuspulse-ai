# CampusPulse AI · v0.2

Учебное пространство для GDG Astana: миссии и дедлайны, реалистичный план, материалы и живые GitHub issues. Теперь с опытом, уровнями, достижениями и объяснением «Почему?» у результатов.

**Состояние:** локальная версия. ИИ может работать без API-ключа на компьютере через Ollama/Qwen. Обязательные для хакатона Gemini и Agent Engine сохранены, но облачный запуск отложен владельцем. Полное выполнение облачной части ТЗ пока не подтверждено. Презентация в этой итерации не обновляется.

## Запуск без ключа

На этом Mac откройте **«Запустить CampusPulse.command»** (то же, что «Запустить с локальным ИИ.command»). Для другого компьютера нужны Python 3.11–3.13 или uv, интернет для установки и достаточно памяти для модели.

```sh
git clone https://github.com/tomirizz/campuspulse-ai.git
cd campuspulse-ai
bash scripts/run.sh --local-ai
```

На macOS launcher при необходимости скачивает официальный Ollama, проверяя SHA-256, и локальную модель `qwen3:1.7b` (~1,4 ГБ). Модель и runtime находятся в игнорируемой папке `data/local-ai`, в Git/ZIP не попадают. Повторный запуск использует уже загруженную модель. На Linux/Windows сначала установите [Ollama](https://ollama.com/download), затем используйте тот же Python launcher из окружения проекта. На Windows окружение можно создать `py -3.11 -m venv .venv`, зависимости установить `.venv\Scripts\python -m pip install -r requirements.lock`, запускать `.venv\Scripts\python scripts/local_start.py`.

Сайт: <http://127.0.0.1:8765>. Завершение: Ctrl+C. Если приложение запустило Ollama самостоятельно, оно остановит свой процесс при выходе. Уже работающий Ollama не останавливается.

Для режима **без ИИ**, но с планировщиком, геймификацией и настоящими MCP-инструментами: откройте «Запустить без ИИ.command» или `AGENT_MODE=tools bash scripts/run.sh`. Этот режим явно помечен и не имитирует модель. Модель не заменяется автоматически при ошибке.

Локальный ИИ работает только на loopback; облачные модели Ollama запрещены. Производительность зависит от устройства. «Без API-ключа» не означает «без установки или загрузки модели». Для GitHub нужен интернет; задачи, план, материалы и локальный инференс не требуют облачного аккаунта.

## Что попробовать

1. Добавить задание с курсом, дедлайном и своей оценкой длительности. Нажать на награду → увидеть формулу.
2. Завершить задание → увидеть XP, обновление карты пути и историю начисления. Вернуть в работу → XP исключается. Повторное завершение возвращает прежнюю награду.
3. Открыть «Мой путь»: уровни, серия дней, достижения и условия каждого этапа.
4. Построить «Мою неделю» с дневным лимитом и busy-интервалами. Проверить «Почему?» у блока/риска, экспортировать ICS.
5. Загрузить текстовую лекцию, спросить о ней. Ответ содержит точную цитату, страницу и строку извлечённого текста.
6. Спросить «Почему у меня столько опыта?» или «Составь план недели». Явные запросы метрик идут в обязательный инструмент; значения считает код, модель выбирает факты для объяснения.
7. Спросить «Проверь GitHub issues в googleapis/python-genai» и посмотреть реальный MCP-вызов, URL и время получения.

## Правила: ИИ не является калькулятором

- XP задания: `20 + min(40, 5 × ceil(минуты / 30))`.
- Уровень: `1 + floor(общий XP / 100)`.
- Прогресс и награда рассчитываются из сохранённых записей. Нет случайных наград или оценок способностей.
- Снимок награды создаётся атомарно при первом завершении, не увеличивается от повторных кликов и изменения минут.
- Таймер фокуса не начисляет XP: он не доказывает выполнение работы.
- Коэффициенты — открытые правила продукта, а не научная модель успеваемости.

Для явных запросов метрик источник выбирается фиксированным правилом, которое видно в журнале. Ассистент выбирает ID фактов. Сервер проверяет выбор и подставляет объяснение, подходящее типу источника. Сервер подставляет неизменённые факты и точные цитаты. Модель не может подменить числовой результат, написать отображаемый код или создать свою цитату. Это ограниченный ассистент по источникам, а не универсальный генератор текста. Релевантность выбора модели всё равно нужно оценивать; наличие ссылки само по себе не доказывает правильную интерпретацию.

## Gemini / Agent Engine

`AGENT_MODE=gemini` использует Vertex AI ADC; `AGENT_MODE=remote` вызывает API Agent Engine. `scripts/deploy_agent.py` содержит требуемый `reasoning_engines.ReasoningEngine.create`. Настройки и проверка API описаны в `docs/DEPLOYMENT.md`. Проект: `campuspulse-ai-511817`. Облачная часть требует биллинга владельца; ключи посетителям сайта передаваться не должны.

Gemini и развёртывание **не проверены живьём**. Dockerfile и Firestore adapter подготовлены; Docker/cloud runtime не подтверждены. Локальная Qwen не подменяет эти критерии.

## Проверки

```sh
source .venv/bin/activate
python -m pytest -q
python -m pytest -q -m live  # отдельно: настоящий GitHub запрос
python scripts/verify_local.py  # отдельно: настоящий локальный ИИ, Ollama должен работать
node --check web/app.js
node --check web/game.js
```

Офлайн-набор проверяет формулы, атомарность, повторные награды, сроки, пересечения, изоляцию сессий, загрузки, источники, отбрасывание выдуманных фактов и agent contract. Подмены SDK в тестах явно обозначены и не считаются живым инференсом. Живые проверки фиксируются отдельно в `docs/verification-v0.2.json`.

Ограничения файлов: PDF/TXT/MD, до 5 МБ, 20 страниц и 60 000 символов; сканам нужен OCR. История и источники могут содержать ваш учебный текст; экспорт проверяйте перед публикацией. Локальные модели, базы данных, ключи и `.env` не входят в репозиторий и архив.

Старый `docs/CampusPulse_AI_v1.pptx` сохранён как черновик предыдущей версии. Он не является актуальной презентацией продукта; новую подготовим в конце по запросу владельца.
