## Выбранные продуктовые сценарии

1. Студент добавляет дедлайны и доступность → агент получает задания → планировщик строит выполнимые блоки → сообщает о перегрузке → студент экспортирует календарь.
2. Студент загружает лекцию → Gemini выбирает материал и страницы → даёт объяснение с ссылкой на источник внутри файла. В tools mode доступен только текстовый фрагмент.
3. Студент указывает публичный репозиторий → агент вызывает GitHub через MCP → возвращает актуальные issues с временем получения и URL.
4. Студент просит добавить задание → Gemini вызывает `propose_task` → интерфейс предлагает проверить поля → только пользователь сохраняет запись.

## Когда можно заявлять о полном выполнении ТЗ

Нужны успешный живой запрос Gemini, развёрнутый Agent Engine, проверенный удалённый API и доступная облачная демонстрация. Пока эти шаги не сделаны, корректная формулировка — «локальная v0.1, код облачной интеграции подготовлен». Готовый код не равен успешному облачному развёртыванию.
